===============================================================================
 Trap27_ODRViolation - CDB debug analysis
===============================================================================

QUESTION
  will the linker diagnose two different definitions of the same class in different translation units?

SHORT ANSWER
  not necessarily. The unsafe target is undefined behavior with no diagnostic required: `main.cpp` compiles `Packet` as 4 bytes, while `provider.cpp` compiles it as 16 bytes.



-------------------------------------------------------------------------------
 1. READ THE SOURCE FIRST
-------------------------------------------------------------------------------

Directory contents: main.cpp, packet.hpp, provider.cpp.

packet.hpp:
 1  #pragma once
 2  #include <cstddef>
 3  struct Packet {
 4      int id;
 5  #ifdef EXTRA_FIELD
 6      void* payload;
 7  #endif
 8  };
 9  std::size_t provider_packet_size();

provider.cpp:
 1  #if defined(RUN_UNSAFE_EXAMPLE)
 2  #define EXTRA_FIELD // Only this translation unit sees the extra member: intentional ODR violation.
 3  #endif
 4  #include "packet.hpp"
 5  std::size_t provider_packet_size() { return sizeof(Packet); }

main.cpp:
 1  #include "packet.hpp"
 2  #include <iostream>
 3  int main() {
 4      std::cout << "consumer sizeof(Packet)=" << sizeof(Packet)
 5                << ", provider sizeof(Packet)=" << provider_packet_size() << '\n'; // BP: compare TU assumptions.
 6  }


-------------------------------------------------------------------------------
 2. BUILD WITHOUT A SANITIZER
-------------------------------------------------------------------------------

cmake --build build\cdb --config Debug --target Trap27_ODRViolation Trap27_ODRViolation_unsafe

No sanitizer detects this ODR violation; MSVC ASan is not an ODR checker.


-------------------------------------------------------------------------------
 3. START CDB
-------------------------------------------------------------------------------

cdb -o -y C:\src\cpptraps42\build\cdb\Debug -srcpath C:\src\cpptraps42\ABI_Build\Trap27_ODRViolation C:\src\cpptraps42\build\cdb\Debug\Trap27_ODRViolation_unsafe.exe

Use .symopt-100 and .lines -e first.

-------------------------------------------------------------------------------
 6. WHAT THE MEASUREMENTS PROVE
-------------------------------------------------------------------------------

  Target  |  Consumer TU  |  Provider TU  |  Meaning
  safe  |  4  |  4  |  one layout assumption
  unsafe  |  4  |  16  |  ODR violation, undefined behavior


-------------------------------------------------------------------------------
 7. COMMAND REFERENCE USED HERE
-------------------------------------------------------------------------------

  Command  |  Purpose
  x <module>!*provider*  |  find the linked provider function
  uf provider_packet_size  |  show provider's size constant
  uf main  |  show consumer's size constant
   bp `main.cpp:4`   |  stop before comparison output
  dt <module>!Type  |  normally shows member offsets if type info exists
  ?? sizeof(T)  |  normally evaluates a type when debug info exists
