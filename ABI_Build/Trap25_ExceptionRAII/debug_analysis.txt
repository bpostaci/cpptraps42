===============================================================================
 Trap25_ExceptionRAII - CDB debug analysis
===============================================================================

QUESTION
  does an exception skip cleanup?

SHORT ANSWER
  it skips ordinary statements after the throw, but it does not skip destructors for fully constructed automatic objects. RAII is the cleanup mechanism.



-------------------------------------------------------------------------------
 1. READ THE SOURCE FIRST
-------------------------------------------------------------------------------

Directory contents: main.cpp.

 1  #include <iostream>
 2  #include <mutex>
 3  #include <stdexcept>
 4  int main(){ std::mutex m; try { std::scoped_lock lock(m); // BP: resource tied to scope.
 5          throw std::runtime_error("failure"); // Destructor unlocks during unwinding.
 6      } catch(...) { std::cout<<"recovered and unlocked\n"; } }

  Entity  |  Role
  std::mutex m  |  resource
  std::scoped_lock lock(m)  |  RAII owner
  line 5 throw  |  non-local exit
  catch(...)  |  execution resumes after unwinding


-------------------------------------------------------------------------------
 2. BUILD WITHOUT A SANITIZER
-------------------------------------------------------------------------------

cmake --build build\cdb --config Debug --target Trap25_ExceptionRAII

A sanitizer is not useful here. The evidence is call stack order during C++ exception unwinding.

 3. START CDB

The destructor runs inside the exception handler path, then calls unlock. A raw m.unlock() statement after line 5 would not run.


-------------------------------------------------------------------------------
 5. WHY THERE IS NO UNSAFE TARGET
-------------------------------------------------------------------------------

There is no Trap25_ExceptionRAII_unsafe.exe. The source has no RUN_UNSAFE_EXAMPLE branch. The anti-pattern would be manual lock(); throw; unlock();, where the cleanup statement is skipped.


-------------------------------------------------------------------------------
 6. WHAT THE MEASUREMENTS PROVE
-------------------------------------------------------------------------------

  Measurement  |  Evidence  |  Meaning
  before throw  |  lock = (locked)  |  resource is held
  exception  |  C++ EH exception  |  unwinding begins
  destructor  |  ~scoped_lock` under `_CxxFrameHandler4  |  RAII cleanup runs
  unlock  |  unlock` called by destructor  |  resource is released


-------------------------------------------------------------------------------
 7. COMMAND REFERENCE USED HERE
-------------------------------------------------------------------------------

  Command  |  Purpose
  bm ...scoped_lock...  |  break in constructor/destructor
   bp `main.cpp:5`   |  stop before throw
  dv /t /v  |  inspect locals
  k  |  show unwinding and cleanup stack
