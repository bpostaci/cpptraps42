# Trap22_VolatileIsNotSync - CDB debug analysis

Question: does `volatile bool ready` synchronize a payload between threads?

Short answer: no. `volatile` is not a C++ synchronization primitive. CDB can show the release/acquire shape in the safe target and the missing guarantee in the unsafe target, but it is not a detector. Use ThreadSanitizer with Clang on Linux or WSL; MSVC has ASan only, not TSan or MSan.

---

## 1. Read the source first


 6      int payload = 0;
 8      volatile bool ready = false; // anti-pattern
 9      std::jthread writer([&] { payload = 42; ready = true; });
11          while (!ready) { std::this_thread::yield(); }
12          std::cout << payload << '\n'; // data race; use TSan
15      std::atomic<bool> ready{false};
18          ready.store(true, std::memory_order_release); // release publishes payload
21          while (!ready.load(std::memory_order_acquire)) { std::this_thread::yield(); }
22          std::cout << payload << '\n';


| Entity | Safe target | Unsafe target |
|---|---|---|
| flag | `std::atomic<bool>` | `volatile bool` |
| publish | release store | ordinary volatile write |
| observe | acquire load | ordinary volatile read |
| payload | happens-before protected | data race |

## 2. Build without a sanitizer

Use the existing `build\cdb\Debug` binaries. Do not clean or rebuild. MSVC's sanitizer support does not include TSan or MSan.

MSVC's legacy `/volatile:ms` behavior is not portable C++ synchronization and must not be relied on.

---

## 6. What the measurements prove

The safe target has an explicit release store and acquire load; the reader sees payload `42` through that edge. The unsafe target shows plain addresses and volatile state, not synchronization. A successful debugger run proves nothing about thread safety.

| Command | Purpose |
|---|---|
| `bp `main.cpp:18`` | release store |
| `bp `main.cpp:21`` | acquire load |
| `bp `main.cpp:22`` | payload read |
| `?? ready` | inspect flag type |
| `?? *this` | inspect lambda captures |
| `dd @$t1 L1` | dump payload word |
| `~`, `k` | thread and stack context |

## 9. Tool limits

| Tool | Use here | Limitation |
|---|---|---|
| CDB | explains locations and captures | not a race detector |
| MSVC ASan | memory bugs | no TSan/MSan in MSVC |
| TSan | primary race detector | Clang/Linux or WSL |
| `volatile` | special object access | not synchronization |
