TRAP03_UNINITIALIZEDMEMORY - CDB DEBUG ANALYSIS

QUESTION
   if a debug session prints a repeatable bit pattern for an uninitialized object, did C++ give that object a value?

SHORT ANSWER
   no. The pattern is debugger evidence, not a language value. MSVC's warning/runtime check is the primary evidence for the scalar; Debug CRT fill bytes help explain what storage looked like in this build.



-------------------------------------------------------------------------------
 1. READ THE SOURCE FIRST
-------------------------------------------------------------------------------

main.cpp (47 lines). The three variants are the automatic scalar, new Point versus new Point{}, and an aggregate that is either fully value-initialized by rules or not initialized at all.

   1  #include <iostream>
   3  // Type 1: an automatic scalar has no value until one is established.
   4  void uninitialized_local() {
   6      int count; // unsafe: no value has been established.
   7      std::cout << "local: " << count << '\n'; // BP
   9      int count{}; // safe: zero.
  10      std::cout << "local: " << count << '\n';
  14  // Type 2: new T default-initializes a POD; only new T{} zero-initializes it.
  15  struct Point { int x; int y; };
  19      Point* p = new Point; // unsafe: members indeterminate.
  20      std::cout << "new: " << p->x << ',' << p->y << '\n'; // BP
  23      Point* p = new Point{}; // safe: zeroes both members.
  29  // Type 3: a partial aggregate initializer only looks complete.
  30  struct Config { int retries; int timeout; int backoff; };
  34      Config c; // unsafe: every member indeterminate.
  35      std::cout << "aggregate: " << c.retries << ',' << c.timeout << ',' << c.backoff << '\n'; // BP
  37      Config c{3}; // safe: remaining members become zero.
  42  int main() { uninitialized_local(); default_vs_value_new(); partial_aggregate(); }

  Entity    Safe invariant    Unsafe observation
  count    value-initialized to zero    automatic storage contains no C++ value
  Point    new Point{}` zero-initializes    new Point` leaves POD members indeterminate
  Config    aggregate remainder is value-initialized    no initializer means no member has a value



-------------------------------------------------------------------------------
 2. BUILD WITHOUT A SANITIZER
-------------------------------------------------------------------------------

  cmake -S . -B build\cdb -DTRAPS_BUILD_UNSAFE=ON -DTRAPS_SANITIZER=none
  cmake --build build\cdb --config Debug --target Trap03_UninitializedMemory Trap03_UninitializedMemory_unsafe

The build already exists for this lab. MSVC has AddressSanitizer, but not MemorySanitizer; uninitialized reads are primarily found by compiler warnings such as C4700, runtime checks in Debug, or Clang MemorySanitizer on a supported platform. Debug fill bytes are a CRT courtesy, not a C++ value.

-------------------------------------------------------------------------------
 6. WHAT THE MEASUREMENTS PROVE
-------------------------------------------------------------------------------

  Variant    Safe measurement    Unsafe measurement    Meaning
  scalar    00 00 00 00` and `count = 0    runtime check: variable used without initialization    C4700/runtime check is the diagnosis; bytes are supporting evidence
  dynamic object    two zero members    cd cd cd cd ...    Debug CRT marked newly allocated storage, not a language value
  aggregate    3,0,0    stack `cc cc ...    no initializer leaves all automatic members indeterminate

0xCD is allocated-but-uninitialized heap storage in this Debug CRT. 0xCC is the stack fill used by this MSVC debug configuration. Treat both as clues only; Release builds need not write them.

 7. COMMAND REFERENCE USED HERE
-------------------------------------------------------------------------------

  Command    Purpose
  .symopt-100    allow local names such as `count`, `p`, and `c

  db addr L4    dump raw bytes
  g    continue to the next stop

-------------------------------------------------------------------------------
 9. TOOL LIMITS
-------------------------------------------------------------------------------

  Tool    Reports this trap    Limitation
  MSVC warning/runtime check    yes for simple scalar    not every uninitialized read is diagnosed
  CDB + Debug fills    shows storage pattern    fill bytes are not C++ values and are Debug-only
  AddressSanitizer    no    ASan is not MemorySanitizer
  Release build    unreliable    optimizer may remove or transform the read
