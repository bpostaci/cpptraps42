QUESTION
  Why can values that print as simple decimals fail equality tests?

SHORT ANSWER
  The stored IEEE-754 values are not the rounded decimal display. This is defined floating-point arithmetic, not a sanitizer-detectable fault.

-------------------------------------------------------------------------------

-------------------------------------------------------------------------------

main.cpp (numbered). The BP: comments mark the intended stops.

   7  // Type 1: decimal literals are not representable in binary, so exact equality fails.
   8  void exact_equality_fails() {
   9  	const double sum = 0.1 + 0.2;
  10  	std::cout << std::setprecision(20) << "0.1+0.2 = " << sum << '\n';
  11  	std::cout << "sum == 0.3 : " << std::boolalpha << (sum == 0.3) << '\n'; // BP: false.
  12  	std::cout << "difference : " << std::setprecision(6) << (sum - 0.3) << '\n';
  13  }
  14  
  15  // Type 2: compare with a tolerance that scales with the magnitude of the operands.
  16  static bool nearly_equal(double a, double b, double relative = 1e-9, double absolute = 1e-12) {
  17  	if (a == b) { return true; } // Handles equal finite values and same-sign infinities.
  18  	if (!std::isfinite(a) || !std::isfinite(b)) { return false; }
  19  	const double diff = std::fabs(a - b);
  20  	const double scale = std::max(std::fabs(a), std::fabs(b));
  21  	return diff <= std::max(absolute, relative * scale); // Hybrid absolute/relative tolerance.
  22  }
  23  
  24  void tolerant_comparison() {
  25  	std::cout << "nearly_equal(0.1+0.2, 0.3) : " << std::boolalpha
  26  			  << nearly_equal(0.1 + 0.2, 0.3) << '\n';
  27  	std::cout << "nearly_equal(1e9+1, 1e9)   : "
  28  			  << nearly_equal(1e9 + 1.0, 1e9) << '\n'; // Absolute epsilon alone would be wrong here.
  29  }
  30  
  31  // Type 3: accumulation and non-finite values break loop conditions built on equality.
  32  void accumulation_and_nan() {
  33  	double running = 0.0;
  34  	for (int i = 0; i < 10; ++i) { running += 0.1; } // Error compounds every iteration.
  35  	std::cout << "sum of ten 0.1 == 1.0 : " << std::boolalpha << (running == 1.0) << '\n';
  36  
  37  	for (int i = 0; i < 10; ++i) {         // Integer loop counter: exact, terminates predictably.
  38  		const double step = i * 0.1;
  39  		(void)step;
  40  	}
  41  
  42  	const double nan_value = std::nan("");
  43  	std::cout << "nan == nan : " << (nan_value == nan_value)             // BP: always false.
  44  			  << "  isnan    : " << std::isnan(nan_value) << '\n';       // The correct test.
  45  }
  46  
  47  int main() {
  48  	exact_equality_fails();
  49  	tolerant_comparison();
  50  	accumulation_and_nan();
  51  }

  NAME          ROLE                INVARIANT TO CHECK                                 
  sum           double              stored bits, not rounded text, decide equality     
  nearly_equal  hybrid tolerance    absolute and relative scales must fit the magnitude
  running       accumulated double  repeated rounding moves it away from 1.0           
  nan_value     quiet NaN           NaN is unordered and compares unequal to itself

 5. WHY THERE IS NO _UNSAFE TARGET
-------------------------------------------------------------------------------

There is no `_unsafe` executable because exact floating-point equality, tolerance checks, accumulation error, and NaN comparison are all defined behaviour. Wrong means the comparison encoded the wrong numerical invariant. The debugger is useful because it exposes the stored bits and the high-precision values.

-------------------------------------------------------------------------------
 6. WHAT THE MEASUREMENTS PROVE
-------------------------------------------------------------------------------

  VARIANT           MEASUREMENT             OBSERVED                               MEANING                                     
  exact equality    sum bits vs 0.3 bits    3fd3333333333334 vs 3fd3333333333333   adjacent representable doubles are not equal
  scaled tolerance  diff vs relative*scale  5.55e-17 <= 3.0e-10; 1 <= 1.000000001  relative tolerance matches magnitude        
  accumulation      ten tenths              0.99999999999999988898                 loop equality against 1.0 is brittle        
  NaN               nan == nan              false                                  use `isnan`, not equality                   

The program is not corrupt. The raw bits and high-precision values show exactly why the printed rounded form is an insufficient invariant.
