===============================================================================
 Trap15_PointerProvenance - CDB debug analysis
===============================================================================

QUESTION
  if two pointers have the same numeric value, may both be used to read the object?


SHORT ANSWER
  no. Numeric equality is not lifetime, ownership, or provenance. CDB can show that bytes agree or look plausible; the C++ abstract machine still decides whether the access is valid.

-------------------------------------------------------------------------------

1. Read the source first


 1  #include <cstdint>
 2  #include <iostream>
 3  #include <memory>
 4  int main() {
 5      auto owner = std::make_unique<int>(42);
 6      int* original = owner.get();
 7  #if defined(RUN_UNSAFE_EXAMPLE)
 8      const auto address = reinterpret_cast<std::uintptr_t>(original);
 9      int* reconstructed = reinterpret_cast<int*>(address);
10      owner.reset();
11      std::cout << *reconstructed << '\n'; // BP
12  #else
13      int* observer = original;
14      std::cout << *observer << '\n'; // BP
15  #endif
16  }


   Entity    Meaning   
  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  
   `owner`    owns the `int` lifetime   
   `original`    pointer obtained while the object is live   
   `address`    integer copy of the pointer value   
   `reconstructed`    pointer recreated from the integer   

-------------------------------------------------------------------------------

2. Build without a sanitizer

Use the existing Debug executables in `build\cdb\Debug`. ASan can diagnose this use-after-free variant, but it is not a general provenance model. The non-sanitized run lets the Debug CRT fill bytes remain visible.

-------------------------------------------------------------------------------

3. Start CDB

Use `-y C:\src\cpptraps42\build\cdb\Debug` and `-srcpath C:\src\cpptraps42\ObjectModel\Trap15_PointerProvenance`. The script begins with `.symopt-100` and `.lines -e` so locals and line breakpoints work.

6. What the measurements prove

   Measurement    Before `reset()`    After `reset()`   
  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  
   `original`    `1b1b9e4ac30`    `1b1b9e4ac30`   
   `reconstructed`    `1b1b9e4ac30`    `1b1b9e4ac30`   
   raw pointer inside `owner`    `1b1b9e4ac30`    `00000000`   
   bytes at address    `2a 00 00 00 ...`    `ee fe ee fe ...`   
   read result    `42` while live    `-17891602` after lifetime ended   

The divergence is between numeric equality and lifetime/provenance. The debugger can show the same address; it cannot grant permission to dereference it.

-------------------------------------------------------------------------------

7. Command reference used here

   Command    Why type it   
  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  
   `?? (void*)p`    compare numeric pointer values   
   `db @@c++(p) L10`    inspect bytes at the address   
   `dqs @@c++(&owner) L1`    inspect the raw pointer inside `unique_ptr`   
   `dv /t /v`    compare locals at the same stop   
   `bp main.cpp:12` / `bp main.cpp:13`    bracket the lifetime-ending event

9. Tool limits

   Tool    Reports this trap    Limitation   
  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  -------------------------------------------------------------------------------  
   CDB    shows numeric equality and heap bytes    not a provenance oracle   
   Debug CRT fills    show lifetime ended here    Debug-only courtesy   
   AddressSanitizer    catches the use-after-free variant    not a general provenance checker   
   MSVC warnings    no    the cast syntax is well formed
