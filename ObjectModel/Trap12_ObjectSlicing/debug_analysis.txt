===============================================================================
 Trap12_ObjectSlicing - CDB debug analysis
===============================================================================

QUESTION
  when a `Derived` is copied into a `Base`, is anything corrupt?


SHORT ANSWER
  no. Slicing is defined behavior. The Base subobject is copied into a new `Base` object; the derived portion is not part of the destination. CDB shows this as a vfptr change from `Derived::vftable` to `Base::vftable`.

-------------------------------------------------------------------------------

1. Read the source first

 5  struct Base { virtual ~Base()=default; virtual void type() const {std::cout<<"Base\n";} };
 6  struct Derived: Base { void type() const override {std::cout<<"Derived\n";} };
 9  void copy_slicing() {
10      Derived d;
11      Base sliced = d; // BP: only Base subobject is copied.
12      std::cout << "copy: "; sliced.type();
13      const Base& polymorphic = d;
14      std::cout << "reference: "; polymorphic.type();
18  void container_slicing() {
20      std::vector<Base> values;
21      values.push_back(Derived{}); // unsafe target: value insertion slices.
24      std::vector<std::unique_ptr<Base>> values;
25      values.push_back(std::make_unique<Derived>()); // safe target: store handles.
31  void print_by_value(Base b) { std::cout << "by value: "; b.type(); }
32  void print_by_reference(const Base& b) { std::cout << "by reference: "; b.type(); }

     Variant      Safe path      Unsafe teaching path     
    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    
     copy initialization      also shows `const Base&`      same defined slice     
     base container      `vector<unique_ptr<Base>>`      `vector<Base>` slices elements     
     parameter      `const Base&`      `Base` by value slices at call boundary     

`Derived` adds no data member in this source; the observable derived part is the vfptr/dynamic dispatch.

-------------------------------------------------------------------------------

2. Build without a sanitizer

This uses the existing `Trap12_ObjectSlicing.exe` and `Trap12_ObjectSlicing_unsafe.exe`. Sanitizers are not expected to report slicing because slicing is defined behavior.

6. What the measurements prove

     Variant      Before      After copy/storage/call      Lesson     
    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    
     copy initialization      `d` has `Derived::vftable`      `sliced` has `Base::vftable`      a new Base object was made     
     base container      safe target stores a pointer to `Derived::vftable`      unsafe target stores a `Base::vftable` element      `vector<Base>` cannot hold a dynamic Derived object by value     
     parameter      caller's `d` has `Derived::vftable`      by-value `b` has `Base::vftable`      slicing occurs at the call boundary     

Nothing is corrupt. The destination type simply has no derived dynamic state.

-------------------------------------------------------------------------------

7. Command reference used here

     Command      Why it was used     
    -------------------------------------------------------------------------------    -------------------------------------------------------------------------------    
     `dt Base` / `dt Derived`      show that this lab's `Derived` adds behavior, not data     
     `dps object L1`      resolve vfptrs to `Base::vftable` or `Derived::vftable`     
     `dqs &values L4`      inspect MSVC vector control pointers     
     `k`      useful for parameter variant call-boundary checks
