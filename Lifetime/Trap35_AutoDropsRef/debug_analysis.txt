===============================================================================
 Trap35_AutoDropsRef - CDB debug analysis
===============================================================================

QUESTION
  When a function or loop gives you a reference, does plain auto keep it?

SHORT ANSWER
  No. Plain auto deduces a value type. The behavior is fully defined, but it may
  silently copy a large object and send later writes to the copy.

-------------------------------------------------------------------------------
 1. READ THE SOURCE FIRST
-------------------------------------------------------------------------------

  10  static Heavy& shared_instance() {
  11      static Heavy instance{"large-payload", 0};
  12      return instance;
  13  }
  16  void auto_copies_a_reference() {
  17      auto copy = shared_instance(); // BP: deduced as Heavy, not Heavy& - a full copy is made.
  18      copy.hits = 42;                // BP: mutates the copy; the shared object is untouched.
  21      auto& reference = shared_instance(); // 'auto&' keeps the binding to the original.
  22      reference.hits = 42;
  27  void range_for_copies_elements() {
  28      std::vector<Heavy> items(3, Heavy{"element", 0});
  29      for (auto item : items) { item.hits = 1; } // BP: each iteration copies and discards.
  30      std::cout << "by value: items[0].hits=" << items[0].hits << '\n';
  32      for (auto& item : items) { item.hits = 1; } // Mutating loop: bind by reference.
  33      std::cout << "by ref  : items[0].hits=" << items[0].hits << '\n';
  40  void keeping_the_exact_type() {
  41      Heavy& source = shared_instance();
  42      decltype(auto) exact = shared_instance(); // Deduces Heavy&, preserving the reference.
  43      exact.hits = 7;

  VARIANT                         COPYING FORM             CORRECT FORM
  function returning reference    auto copy                auto& reference
  range-for                       for (auto item : items)  for (auto& item : items)
  exact return semantics          plain auto would copy    decltype(auto)

-------------------------------------------------------------------------------
 5. WHY THERE IS NO UNSAFE TARGET
-------------------------------------------------------------------------------

Trap35_AutoDropsRef_unsafe.exe does not exist. Plain auto copying a reference
result is not undefined behavior; it is a defined copy. A sanitizer has no
invalid access to report. The correct evidence is address divergence and
unchanged source state.

-------------------------------------------------------------------------------
 6. WHAT THE MEASUREMENTS PROVE
-------------------------------------------------------------------------------

  CASE                  DEDUCED VARIABLE       SOURCE               RESULT
  auto copy             00000053`af1dfcc8      00007ff7`f8585518    different
  auto& reference       00007ff7`f8585518      00007ff7`f8585518    same
  range auto item       00000053`af1dfc88      00000225`b1295620    discarded
  range auto& item      00000225`b1295620      00000225`b1295620    hits -> 1
  decltype(auto) exact  00007ff7`f8585518      00007ff7`f8585518    preserved

The first and third rows diverge. That divergence is the lesson.

 7. COMMAND REFERENCE USED HERE
-------------------------------------------------------------------------------

  ?? &copy                         show stack address of copied object
  dv /t /v                         show references as bound addresses
  bp module!function+offset        stop inside generated one-line range-for code
  ? @rsp+0a8                       compute by-value loop item copy address
  ? poi(@rsp+100)                  read by-reference loop item element address
  ?? items._Mypair..._Myfirst      compare with vector's first element
  bc n                             clear one-shot breakpoints in a loop
